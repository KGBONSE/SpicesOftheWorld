## What this skill does

Turns a topic (researched) or a set of stats already in hand into one flat-design
infographic image — a single PNG someone would actually save and share. Text is
built as real HTML/CSS and captured with a headless browser screenshot, not
generated by an image model, because AI image generation is unreliable at
rendering exact numbers, labels, and spelling — the whole point of an
infographic is that the numbers are right.

## Trigger phrases

"/explainer-infographic", "make an infographic about X", "turn this into an
infographic", "infographic on X", "content repurpose" step-3-and-beyond does
NOT include this skill (that one only chains blog-post/newsletter/linkedin-post) —
this is a separate, standalone skill.

## Step 1 — Get the input

Ask, if not already given: do you have a **topic** (I'll research a few real
facts) or a **specific set of stats/facts** already in hand (I'll use exactly
those)?

- **Topic only** — research 3–6 real, verifiable, attributable facts or
  stats with WebSearch/WebFetch. Never invent a number. Keep a short source
  name for each fact (a named source, not just "studies show").
- **Given stats** — use exactly what's given; don't add interpretation or
  round numbers beyond what was stated.
- **Fudi People / spice topic** — check `knowledge-base/`, `scripts/`, and
  `docs/` in this project first, before general web research (same sourcing
  rule as the other content skills), and follow the shared brand rules in
  `agents/marketing-team.md`: no health claims beyond "research suggests",
  `[VERIFY ALLERGENS AGAINST SUPPLIER]` on any allergen mention, only
  promote published products, and citation to Dr Farrimond for any *Science
  of Spice* fact.

## Step 2 — Design the layout

Read the `dataviz` skill (stat-tile, color, and layout guidance) and the
`artifact-design` skill once before writing the page. Structure:

- **Headline** — the topic, short and concrete, top third of the canvas
- **One-line subhead** — the hook, why this is worth a second look
- **3–6 stat tiles or fact blocks** — each a short label + the number/fact,
  one line of context max per tile
- **Source line** — small text at the bottom naming where each fact came from
- Flat design only: solid colors, simple shapes/icons/emoji as accents, no
  photoreal imagery. Keep to one accent color plus neutrals so it reads as
  one system, per the dataviz palette method.

## Step 3 — Build and render

1. Write a single self-contained HTML file to a scratch path (inline all
   CSS; Google Fonts is fine, nothing else external) using
   `template.html` in this skill's folder as the starting structure. The
   root element must be sized to exactly the target canvas in px — default
   **1080x1350** (portrait, fits Instagram/Pinterest-style "save and share"
   feeds) — override only if the user asks for a different shape (e.g.
   1080x1080 square, 1080x1920 story).
2. Render it to PNG with the bundled script:
   `python3 .claude/skills/explainer-infographic/scripts/render.py <input.html> <output.png> [width] [height]`
   (Playwright/Chromium are pre-installed in this workspace — don't try to
   install anything.)
3. Open the PNG and eyeball it: text not clipped or overlapping, tiles
   aligned, nothing running off the 1080x1350 canvas. Re-render after any CSS fix.

## Step 4 — Save and deliver

Save both files to `marketing/infographics/YYYY-MM-DD-<slug>.png` and
`.html` (the HTML stays as the editable source). Deliver the PNG to the
user directly (not just saved in the repo) so they can see and share it
immediately.

## Step 5 — Summarize

Show: the topic, the facts used with their sources, the canvas size, and
the exact file paths. Roll up a short "Needs Kofi" list for anything
unverified, borderline as a health/medical claim, or touching an
unpublished product.

## Rules

- Never invent a stat or fact. If good numbers can't be found, say so and
  offer fewer, verified facts rather than padding with guesses.
- No health claims beyond "research suggests" framing (shared rule).
- Flat design, real rendered text — no AI-generated image for the graphic
  itself. Higgsfield can still be used separately for a decorative photo
  background behind other content, but not for this skill's core deliverable.
- Keep the source line honest and visible — an infographic without
  attribution is not shareable in good conscience.

## Adding to content-repurposing later

This is a separate skill from the blog-post/newsletter/linkedin-post trio
run by `content-repurposing`. If a video source lends itself to a stat-heavy
visual, this can be run alongside that skill on the same source — just
invoke it separately, same as any other content skill.
